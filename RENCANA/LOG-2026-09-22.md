### Penanganan Konflik Identitas Node (`node-1` Mendaftar Dua Kali)
- **Latar Masalah:** Jika ada dua laptop menjalankan worker dengan argumen default atau sama persis (`--node-id=node-1`), registrasi tanpa penjagaan akan saling menimpa (*unconditional overwrite*), memicu penolakan heartbeat bergantian akibat perbedaan `session_id`, dan menyebabkan fenomena *flapping/ping-pong* tak berujung.
- **Mekanisme Penjagaan (`internal/registry/registry.go`):**
  - **Kasus 1 — Restart di Laptop yang Sama (`existing.AdvertiseAddr == advertiseAddr`):** Diterima langsung dan metadata diperbarui tanpa menunggu batas timeout kegagalan node.
  - **Kasus 2 — Perebutan Identitas oleh Laptop Lain (`existing.AdvertiseAddr != advertiseAddr` & `existing.Status == StatusAlive` & `time.Since(lastHB) < timeout`):** Ditolak dengan status `Accepted: false` dan pesan peringatan: `"node ID '%s' sedang aktif digunakan oleh worker di %s (gunakan flag --node-id berbeda)"`.
  - **Kasus 3 — Pengambilalihan Pasca Kematian Node (`StatusDead` atau `time.Since(lastHB) >= timeout`):** Diterima untuk mengakomodasi node yang berganti IP (DHCP lease baru).
- **Integrasi RPC & Registry Test:**
  - Metode baru `RegisterNode(nodeID, sessionID, advertiseAddr, capacity) (bool, string)` ditambahkan ke registry.
  - `CoordinatorServer.Register` di `internal/rpc/rpc.go` mengembalikan pesan error konflik langsung ke worker.
  - Ditambahkan unit test `TestKonflikNodeIDSesiBeda`, `TestRestartNodeSamaDiterima`, dan pembaruan `TestSesiBaruMenimpaLama` pada `internal/registry/registry_test.go`.

### Alokasi Otomatis Node ID oleh Master (*Dynamic Auto-Assign Node ID*)
- **Kebutuhan Operator:** Operator worker tidak perlu lagi menghafal dan mengetik `--node-id=node-1`, `--node-id=node-2`, atau `--node-id=node-3`. Seluruh laptop worker cukup mengeksekusi perintah yang sama persis: `.\dist\distapi.exe --mode=node --master=<IP>:9000 --token=<token> --tui`.
- **Mekanisme Master (`internal/registry/registry.go`):**
  - Parameter `--node-id` secara default bernilai `"auto"`.
  - Saat worker menghubungi `CoordinatorServer.Register`, Master memeriksa apakah `nodeID == "" || nodeID == "auto"`.
  - Jika host (IP) sudah pernah terdaftar, Master mengalokasikan kembali ID lama (*sticky assignment*).
  - Jika host baru, Master mencari indeks terkecil yang belum terpakai (`node-1`, `node-2`, `node-3`, dst).
  - Master mengembalikan `ASSIGNED:<assignedID>|<msg>` melalui `RegisterResponse.Message`.
- **Integrasi Worker & TUI (`cmd/distapi/main.go`, `internal/tui/node.go`):**
  - Worker membaca assigned ID dari respons registrasi master, mengupdate `cfg.NodeID` dan memanggil `state.SetNodeID(assignedID)`.
  - TUI dan log CLI worker langsung mengonfirmasi dan menampilkan: `[Node Terdaftar] Identitas Dialokasikan: node-1`.
  - Heartbeat selanjutnya dikirim menggunakan `assignedID`.
- **Pengujian:**
  - `internal/registry/registry_test.go`: `TestAutoAssignNodeID` memverifikasi pendaftaran berurutan `node-1`, `node-2`, `node-3`, serta sticky ID saat restart.
  - `internal/rpc/integration_test.go`: `TestIntegration_AutoAssignNodeID` memverifikasi negosiasi gRPC end-to-end.
